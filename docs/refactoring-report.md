# 리팩터링 최종 보고서

작성일: 2026-07-24

작업 브랜치: `codex/refactor-foundation`

상태: 구현과 검증 완료. 아직 Raspberry Pi에 배포하지 않았습니다.

## 한눈에 보는 결과

이번 작업은 새 기능을 크게 늘리기보다, 기존 봇을 고칠 때 실제 데이터와 사용자
기능을 망가뜨릴 가능성을 낮추는 작업입니다. 음악, 즐겨찾기, 경험치, 생일, 요약,
Watch Together의 기존 사용 방식을 유지하면서 검사 장치와 실패 복구 절차를
보강했습니다.

추가 요청에 따라 백업은 사용자 ID와 음악 정보뿐 아니라 파일의 구조까지 전부
암호화하도록 바꿨습니다. Watch Together는 새 방이 생기면 개인 관리 서버에
종료 버튼을 띄우며, 관리자만 그 버튼으로 방을 정리할 수 있습니다. 쓰이지 않는
음성 수신·음성 인식·옛 검색 도구는 제거했고 Gemini 연결 방식과 HTTP 테스트
도구는 현재 패키지로 교체했습니다.

## 그대로 유지한 사용자 동작

- 기존 Discord 명령, 버튼 이름과 공개·비공개 응답 방식
- 음악 전용 채널의 주크박스 사용 흐름
- 사용자 기준으로 어느 서버에서나 공유되는 즐겨찾기
- 음악 대기열, 반복, 자동 재생과 재시작 상태 형식
- 기존 SQLite 표와 저장 데이터 형식
- Watch Together 주소, 브라우저 통신 형식과 자동 종료 시간
- 최신 원격 백업을 `db-backup` 브랜치 한 곳에서 관리하는 운영 방식

- 설치된 패키지 충돌 검사: 통과
- Raspberry Pi용 Bash 스크립트 문법 검사: 통과
- Git 공백 오류 검사: 통과

자동 검사는 다음을 포함합니다.

- 올바른 키로 새 백업이 복구되고, 잘못된 키로 운영 DB가 교체되지 않는지
- 예전 백업 형식도 복구할 수 있는지
- Watch Together 관리자 권한, 강제 종료와 재시작 뒤 정리
- Gemini 비동기 요청과 연결 종료

- 자동 업데이트·백업의 실패 처리와 복구 순서

테스트는 실제 Discord, Gemini, YouTube, GitHub, systemd에 접속하지 않습니다.
외부 동작은 가짜 연결로 대신 검사했습니다.

## 실제 운영 데이터

이번 작업과 테스트는 다음 운영 파일의 내용을 바꾸지 않았습니다.

- `data/bot_database.db`
- `data/database_backup.sql`
- `data/music_state.json`이 존재한다면 해당 파일

`envtemplate.txt`의 사용자 변경도 보존했습니다. 새 전체 암호화 백업은 배포 후 다음
정기 백업이 실행될 때 처음 만들어집니다. 현재 로컬의 기존 백업 파일은 이 작업에서
다시 만들지 않았습니다.

## 아직 남은 위험과 결정

1. **실행 중인 SQLite 파일은 전체 암호화가 아닙니다.** 원격 백업은 모두 암호화하지만,
   Pi 자체와 `.env` 키가 함께 탈취되는 상황까지 막지는 못합니다. SQLCipher 같은
   실행 DB 암호화는 별도 고위험 작업으로 남겨 두는 편이 안전합니다.
2. **정상 백업이 전혀 없을 때 새 DB로 시작할지 정책이 미정입니다.** 현재는 데이터
   유실을 숨기지 않기 위해 자동으로 빈 DB를 만들지 않고 실행을 멈춥니다.
3. **생일 기능의 직접 자동 검사가 부족합니다.** 등록, 삭제, 알림 시각은 다음
   리팩터링 전에 현재 동작을 기록하는 검사가 필요합니다.
4. **Watch Together 초대 링크 자체에는 로그인 제한이 없습니다.** 관리자 종료 수단은
   생겼지만, 링크를 아는 사람이 들어오는 것을 사전에 막는 기능은 아닙니다.
5. **Python 3.12의 `audioop` 지원 종료 경고가 하나 남습니다.** 이 코드는 Discord
   음성 재생 볼륨 처리에 실제로 사용되므로 지금 제거하면 음악이 깨질 수 있습니다.
   Python 3.13 전환을 별도 환경에서 먼저 시험해야 합니다.
6. **정확히 같은 설치 환경을 재현하는 잠금 파일은 아직 없습니다.** 현재 버전 범위는
   관리하지만 Pi와 PC의 모든 하위 패키지를 완전히 동일하게 고정하지는 않습니다.

## Git 반영 사항

과거에 `main`이 추적하던 `data/database_backup.sql`은 내용은 건드리지 않은 채
현재 코드 브랜치의 추적 목록에서 제외했습니다. 로컬 파일과 내용은 그대로
보존했습니다. Pi의 최신 백업은 계속 `db-backup` 브랜치에서만 관리합니다.

변경은 책임별 작은 커밋으로 나누고, 마지막에 전체 84개 검사를 다시 실행합니다.
문제가 생기면 해당 코드 커밋만 `git revert`하고 운영 DB와 백업은 그대로 두는
방식으로 되돌립니다.
