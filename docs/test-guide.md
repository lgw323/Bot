# 봇 건강 검진(Test) 가이드 🩺

이 문서는 현재 자동 테스트가 확인하는 동작, 실행 방법과 실제 데이터 보호 범위를
설명합니다. 기능 설명과 실행 준비는 루트 `README.md`, 제품 의도는
`project-context.md`에서 관리합니다.

---

## 💡 1. 시스템 안정성 개요: 테스트(건강 검진)가 왜 필요할까요?
로봇청소기가 벽에 부딪혔을 때 어떻게 피해야 할지 매번 상황을 만들어 알려주는 것을 **'테스트'**라고 합니다.
디스코드 봇도 마찬가지입니다. 사용자가 주요 기능을 이용하는 상황을 미리 재현하면, 코드 변경 후 기존 기능이 망가졌는지 실제 서버에 적용하기 전에 확인할 수 있습니다.

이 **'건강 검진 코드(Test Code)'**는 실제 Discord 서버에서 봇을 켜지 않고도 확인된 동작을 반복 검사하는 안전망입니다. 모든 기능을 보장하는 것은 아니며, 아직 테스트가 없는 기능은 별도로 표시합니다.

---

## 📋 2. 기능별 검사 항목 (어떤 상황을 방어하나요?)

다음은 우리의 봇이 어떤 가상의 훈련을 거치는지 일상적인 언어로 정리한 표입니다.

| 기능 이름 | 검사 항목 (이런 상황을 방어합니다!) |
| :--- | :--- |
| **🗄️ 데이터베이스 (DB)** | 테이블 생성, 경험치·음악 설정·즐겨찾기 저장과 백업·복구를 검사합니다. 새 백업은 SQL 구조, 사용자 ID, 음악 정보까지 파일 전체가 암호화되는지 확인합니다. 예전 방식으로 일부 값만 암호화한 백업도 복구할 수 있는지 검사합니다. 키 누락·덤프 생성 실패·잘못된 SQL이 마지막 정상 백업을 덮어쓰지 않는지, 잘못된 키로 운영 DB를 교체하지 않는지도 확인합니다. |
| **📈 레벨링 (경험치)** | 글자 길이 계산, 레벨별 필요 경험치, 메시지 작성 시 경험치 저장 요청을 검사합니다. |
| **📝 로깅 (알람 창구)** | 오류 로그를 Discord로 보내는 처리와 메시지가 너무 길 때 잘라 보내는 처리를 검사합니다. |
| **🎶 음악 시스템 (Music)** | YouTube 주소 판별, 곡과 재생 상태 생성, 기존 JSON 형식의 재시작 상태 저장을 검사합니다. 저장 실패 시 이전 상태 파일을 보존하는지, 손상된 JSON을 삭제하지 않는지와 음성 채널·재생 위치·대기열·반복·자동 재생 복원도 확인합니다. |
| **🎬 시청방 (Watch Together)** | 세션과 공유 대기열 저장, 웹 요청 응답, 빈 세션 자동 소멸을 검사합니다. 새 세션이 개인 관리 서버에 알려지는지, 관리자만 강제 종료할 수 있는지, 종료할 때 접속자·초대 메시지·저장 기록이 함께 정리되는지와 재시작 뒤 남은 세션을 정리하는지도 확인합니다. |
| **🤖 대화 요약 (AI)** | 메시지 수집과 오래된 기록 정리, 요약용 문장 구성과 응답 형식 해석을 검사합니다. 최신 Gemini 연결 방식의 비동기 요청과 종료 시 연결 정리도 확인합니다. |
| **🎂 생일 관리 (Birthday)** | 현재 생일 등록·삭제·정기 알림을 직접 검사하는 테스트는 확인되지 않았습니다. |
| **🔄 자동 업데이트** | 일반 패키지를 무조건 최신화하지 않는지, `yt-dlp`만 별도 갱신하는지, 패키지를 코드보다 먼저 준비하는지와 실패 시 재시도·코드 복구 경로가 있는지 검사합니다. 새 코드로 정상 재시작한 뒤에만 폐기된 음성 수신·검색 패키지를 제거하는지도 확인합니다. 실제 Git·pip·systemd 명령은 실행하지 않습니다. |
| **💾 자동 백업** | SQL 생성이 실패하면 이전 파일을 새 백업처럼 올리지 않는지, 원격 업로드가 실패하면 성공으로 끝나지 않는지를 스크립트 내용으로 검사합니다. 실제 백업·Git 업로드 명령은 실행하지 않습니다. |
| **🛠️ 시스템 무결성** | 주요 모듈을 불러올 수 있는지와 Discord 기능 모듈의 기본 진입 함수가 존재하는지 검사합니다. |

음악과 요약 테스트는 종료되지 않은 coroutine을 남기지 않는지도 검사합니다. 내부
비동기 경고를 더 엄격하게 확인할 때는 다음 명령을 사용합니다.

```bash
python -m pytest tests/ -W error::RuntimeWarning -W error::pytest.PytestUnraisableExceptionWarning
```

이 검사는 프로젝트 내부의 미정리 비동기 작업을 오류로 취급합니다. 현재 남은 외부
경고는 Python 3.12의 `audioop` 지원 종료 예고입니다. 이 기능은 Discord 음성 재생의
볼륨 처리에 실제로 필요하므로 제거하지 않았으며, Python 3.13 전환 전에 별도 호환
검증이 필요합니다. Gemini와 HTTP 테스트 도구의 이전 경고는 이번 변경에서 해소했습니다.

## 🚀 3. 일반인용 실행 가이드 (직접 검사해보기)

관리자님이 봇 코드를 조금이라도 수정했거나 업데이트를 받았다면, 봇을 실제 서버에 가동하기 전에 **반드시 건강 검진을 실행**해보세요. 아주 쉽습니다!

### 🖥️ 실행 방법
1. 봇 폴더가 열려 있는 검은색 창(터미널)을 클릭합니다.
2. 아래 명령어를 그대로 복사해서 붙여넣고 키보드 `Enter` 키를 누르세요.
   ```bash
   python -m pytest tests/
   ```

### ✅ 검사 통과 시 화면 (정상)
화면 아래쪽에 실패 없이 **초록색 글씨**로 `passed`가 표시되면 현재 테스트 항목을 통과한 것입니다.

### ❌ 검사 실패 시 화면 (비정상)
만약 화면에 **빨간색 글씨**로 `FAILED` 또는 `ERROR`가 뜬다면 코드나 실행 환경을 확인해야 합니다.
이때는 봇을 켜지 말고 에러 내용을 스크린샷으로 찍어 개발자에게 전달하시면 됩니다!

## 🔒 4. 실제 데이터 보호

`python -m pytest tests/`로 실행되는 모든 테스트는 `tests/conftest.py`가 만든 임시 폴더의
SQLite DB와 SQL 백업만 사용합니다. 저장소의 실제 `data/bot_database.db`와
`data/database_backup.sql`은 테스트 대상으로 사용하지 않습니다.

테스트용 빈 SQL 백업도 임시 폴더에 미리 준비되므로, DB 초기화 테스트가 GitHub의
별도 비공개 저장소의 `db-backup` 브랜치에서 실제 백업을 내려받지 않습니다. 테스트 데이터는 운영 폴더
밖의 pytest 임시 영역에만 남으며 pytest의 임시 파일 관리 대상이 됩니다.

테스트는 재생 상태 파일, 자동 업데이트 재시도 표식과 설치 전 임시 의존성 파일도
Git에 잘못 포함되지 않도록 `.gitignore` 설정을 확인합니다.
